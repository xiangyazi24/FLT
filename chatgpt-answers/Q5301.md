# 1. Why the finite-plus-torsion-free argument is not the right proof

## TwoSurjective does not by itself imply finiteness

Surjectivity of [2] certainly does not imply that a group is finite; for example, every rational vector space is uniquely two-divisible. One can deduce rank zero for a finitely generated abelian group, and hence finiteness, but that requires a genuine finite-generation theorem/instance for this concrete Picard group and a structure-theorem argument. None of that is needed by the current N13 endgame.

## coord_injective is not an additive embedding

The chart field

```javascript
coord_injective : Function.Injective coord
```

only says that coord is injective as a function. It does not say

```javascript
coord (x + y) = coord x + coord y.
```

Therefore an injective set map

```plain text
ker ↪ ℤ₂²
```

or

```plain text
ker ↪ ℚ₂²
```

does not transfer torsion-freeness from the codomain to the kernel. A finite torsion group can inject into the underlying set of ℚ₂².

The actual chart law is intentionally nonlinear. In the checked N13 source, the binary field is

```javascript
add_error_mem :
  ∀ z w i,
    coord (z + w) i - (coord z i + coord w i) ∈
      coordIdeal coord z * coordIdeal coord w
```

and the unary version is

```javascript
double_error_mem :
  ∀ z i,
    coord (2 • z) i - (coord z i + coord z i) ∈
      coordIdeal coord z * coordIdeal coord z.
```

This quadratic error estimate is used to show that doubling raises two-adic coordinate depth by one. It proves

```javascript
N18RouteC.Separated.NSeparated K 2,
```

not that coord is a group embedding.

Thus the correct replacement for steps (c)–(e) is simply:

```javascript
have hsep : N18RouteC.Separated.NSeparated red.ker 2 :=
  kernelDoublingData.separated
```

# 2. The existing direct reduction-injectivity theorem

N13TwoAdicEndgame.lean already proves

```javascript
theorem reduction_injective_of_finite_target
    {G J₂ : Type*}
    [AddCommGroup G] [AddCommGroup J₂] [Finite J₂]
    (red : G →+ J₂)
    (red_surjective : Function.Surjective red)
    (twoSurjective : TwoSurjective G)
    (separated : NSeparated red.ker 2) :
    Function.Injective red
```

and N13MumfordFullKummerTwoSurjective.lean specializes it as

```javascript
theorem reduction_injective_of_finite_image
    {J₂ : Type*} [AddCommGroup J₂] [Finite J₂]
    (red : G →+ J₂)
    (red_surjective : Function.Surjective red)
    (separated :
      N18RouteC.Separated.NSeparated red.ker 2) :
    Function.Injective red.
```

The proof is exactly the desired noncircular descent:

1. Global [2]-surjectivity and surjectivity of red imply [2]-surjectivity on the finite target.

1. On a finite type, surjective [2] is injective.

1. If P ∈ red.ker and P = 2 • Q, then

1. Hence every iterated half of a kernel element can be chosen inside the kernel.

1. NSeparated red.ker 2 forces the original kernel element to be zero.

This route needs neither finite generation nor finiteness of G, and it never claims that the chart coordinate is additive.

# 4. What is still missing from AbelChartData + SmallMumfordRigidity

## Missing fact A: kernel-chart coverage

For an independently defined reduction map

```javascript
red₂ : G →+ J₂
```

let

```javascript
H := red₂.ker.
```

You need either the direct pointwise statement

```javascript
kernel_exists_nearBase :
  ∀ z : H,
    ∃ E : N13RationalKernelDoublingAdapter.NearBaseMumford,
      E.centeredPic =
        N13TwoAdicAbelChartSection.subgroupToPic H z
```

or equivalently a disk-pair version

```javascript
kernel_exists_diskPair :
  ∀ z : H,
    ∃ P : N13TwoAdicAbelChartData.DiskPair,
      N13TwoAdicAbelChartPic.DiskPair.centeredPic P =
        N13TwoAdicAbelChartSection.subgroupToPic H z.
```

This is an existence/coverage theorem. Coordinate injectivity and Mumford rigidity cannot prove it.

The stronger concrete route already packaged in the repository is to prove, directly from z.property : red₂ z = 0, that the canonical normalized representative contracts to the selected special ideal:

```javascript
kernel_map_contract_eq_special :
  ∀ z : H,
    Ideal.map
        N13GeneralizedMumfordReduction.reduceCoordinate
        (N13IntegralModelContraction.contractIdeal
          (N13CanonicalContractionQuotient.graphIdeal
            (N13RationalKernelDoublingAdapter.canonicalMappedSpecialMumford
              (N13TwoAdicAbelChartSection.subgroupToPic H z)).toSemi)) =
      N13SpecialQuotientBasis.specialIdeal.
```

Then form

```javascript
N13RationalKernelDoublingAdapter.CanonicalMappedSpecialFamily H
```

and use the existing graph-recovery theorem to obtain the near-base family.

This is the exact place where the current circular construction must be replaced. If kernel_map_contract_eq_special is proved by invoking the endpoint’s class_eq_iff, the cycle remains. It must instead be proved from the independently defined reduction map and z.property.

## Missing fact B: the unary doubling law

The binary add_error_mem field is unnecessary. The endgame only iterates doubling, so the minimal missing law is

```javascript
N13TwoAdicAbelChartLaw.DoublingLaw
  (fun z => DiskPair.coord (pair z)).
```

The repository has already reduced this to

```javascript
N13RationalKernelDoublingAdapter.FirstJetDoublingCompatibility F.
```

FirstJetDoublingCompatibility.toDoublingLaw combines:

1. comparison of the chosen representative of 2 • z with the square jet of the chosen representative of z; and

1. the already-proved theorem that the square jet is twice the original coordinate modulo the square of the moving coordinate ideal.

Therefore the hard geometric boundary is not all five fields of Chart. It is precisely:

```plain text
kernel coverage / canonical contraction
+ FirstJetDoublingCompatibility.
```

# 6. How to finish class_eq_iff

There are two clean variants.

## Variant A: choose kernel = red₂.ker

This is conceptually the best choice. Once there is an independent theorem identifying specialization of a spread with reduction of its generic rational class, class_eq_iff follows from elementary kernel exactness; reduction injectivity is not even needed.

Let rawGeneric L : G denote the unquotiented rational class of a spread line, and suppose the independent compatibility theorem gives

```javascript
specialClass L = specialClass M ↔
  red₂ (rawGeneric L) = red₂ (rawGeneric M).
```

Then

```plain text
specialClass L = specialClass M
↔ red₂ (rawGeneric L) = red₂ (rawGeneric M)
↔ rawGeneric L - rawGeneric M ∈ red₂.ker
↔ genericClass red₂.ker L = genericClass red₂.ker M.
```

The last equivalence is QuotientAddGroup.eq_iff_sub_mem.

A schematic Lean proof is:

```javascript
theorem class_eq_iff_of_reduction
    (hspecial :
      ∀ L M,
        specialClass L = specialClass M ↔
          red₂ (rawGeneric L) = red₂ (rawGeneric M)) :
    ∀ L M,
      specialClass L = specialClass M ↔
        genericClass red₂.ker L = genericClass red₂.ker M := by
  intro L M
  rw [hspecial L M]
  rw [show
    red₂ (rawGeneric L) = red₂ (rawGeneric M) ↔
      rawGeneric L - rawGeneric M ∈ red₂.ker by
        simp [map_sub, sub_eq_zero]]
  exact QuotientAddGroup.eq_iff_sub_mem.symm
```

The exact orientation of the final .symm depends on the local definition of genericClass, but this is the complete mathematical proof.

## Variant B: first prove red₂ injective, then take kernel = ⊥

After red₂_injective:

```javascript
have hker : red₂.ker = ⊥ :=
  AddMonoidHom.ker_eq_bot.mpr red₂_injective
```

or the corresponding AddMonoidHom/AddMonoidHomClass lemma available in the imported Mathlib version.

Then the spread compatibility theorem and injectivity give

```plain text
special equality
↔ equality after red₂
↔ equality of raw generic rational classes
↔ equality in G ⧸ ⊥.
```

This produces the endpoint’s class_eq_iff with kernel := ⊥.

Variant A is shorter and avoids rewriting the kernel. Variant B is useful if downstream code has already standardized on kernel = ⊥.

# 7. Where the cardinality-19 and cusp facts enter

The card-19 theorem and the cuspidal subgroup are useful, but not in the proposed finite-source argument.

They can establish the target-side hypotheses:

- [Finite J₂] follows from the card-19 computation.

- Surjectivity of red₂ follows if the reductions of the 19 cuspidal classes are shown distinct and the target has exactly 19 elements.

Alternatively, replace J₂ by the image/range of red₂; the range-restricted map is surjective by construction and its target is finite as a subtype of a finite special Jacobian.

What those facts do not provide is the reduction homomorphism itself. A card-19 special set and a ZMod 19 subgroup of G are insufficient unless the code also contains an independently well-defined additive map

```javascript
red₂ : G →+ J₂
```

and a theorem connecting red₂ with specialClass of spread lines. If the only available “reduction map” is N13ReductionClassifier.Data.red, then its Data.exact field is already the desired class_eq_iff; using that object to prove class_eq_iff is circular.

# Final answer

The correct proof does not go through “G finite, kernel finite, coordinate injection into a torsion-free group.” Instead:

1. construct an independent finite-target reduction homomorphism red₂;

1. define H := red₂.ker;

1. prove kernel coverage by the two-disk chart directly from z.property;

1. prove FirstJetDoublingCompatibility for the recovered family;

1. obtain NSeparated H 2 from RationalKernelDoublingData.separated;

1. apply reduction_injective_of_finite_image;

1. derive class_eq_iff from reduction compatibility, either with kernel red₂.ker directly or with ⊥ after injectivity.

Thus four of the chart obligations are already automatic once a faithful kernel-indexed disk-pair realization exists; the nonlinear law is supplied by the first-jet doubling adapter. The genuinely missing independent theorem is kernel-chart coverage (or canonical-contraction-to-special-ideal) from actual reduction-kernel membership.
