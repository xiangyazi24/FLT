# 1. Exact logical content of class_eq_iff

Let

```plain text
rClass : SpreadLine → J(ℚ)
red     : J(ℚ) → J_special
sClass  : SpreadLine → J_special
```

and suppose the intended compatibility is

```plain text
sClass L = red (rClass L).
```

With kernel = ⊥, quotienting does nothing, so the requested equivalence is

```plain text
sClass L = sClass M ↔ rClass L = rClass M.
```

This decomposes into two logically separate statements.

## Preservation of equality

```plain text
rClass L = rClass M → sClass L = sClass M
```

This follows by applying red. In Lean it may require a theorem saying that the two concrete constructions of the class commute with specialization, but it contains no rational-point classification.

## Reflection of equality

```plain text
sClass L = sClass M → rClass L = rClass M
```

Using compatibility, this says

```plain text
red (rClass L - rClass M) = 0
```

and therefore follows from injectivity of red, or merely from injectivity on the subgroup generated by the class differences appearing in the family.

Nothing here says that a line is cuspidal. It says only that two divisor classes which become equal in the special fiber were already equal generically. The endpoint theorem combines this class separation with the first-jet/doubling geometry to obtain cuspidality.

Thus class_eq_iff is strictly different from, and weaker than,

```plain text
∀ P ∈ X_1(13)(ℚ), P is a cusp.
```

There is one formalization caveat: if specialClass is only a combinatorial proxy for a special Picard class rather than literally red ∘ rationalClass, then class_eq_iff may also be packaging the comparison between that proxy and genuine Néron/Picard specialization. That comparison is still independent of the rational-point theorem, but it must not be silently assumed.

# 2. Is J_1(13)(ℚ) ≅ ℤ/19ℤ independent?

## Yes—historically and logically

The classical proof separates three ingredients.

### Ogg's cuspidal subgroup calculation

The differences of the six rational cusps define points of order 19 in the Jacobian, and generate one cyclic subgroup

```plain text
C_cusp ≅ ℤ/19ℤ ⊂ J(ℚ).
```

This uses modular units and divisor computations at the cusps. It does not assume that the cusps are all rational points.

Ogg also computes finite-field point counts. In the standard exposition,

```plain text
#X(𝔽₂) = #X(𝔽₄) = 6,
#J(𝔽₂) = 19,
```

and similarly #J(𝔽₃)=19. Reduction at 2 and 3 then proves that the rational torsion subgroup is exactly cyclic of order 19.

### Mazur–Tate rank-zero descent

The remaining question is whether J(ℚ) has a free part. Mazur and Tate exploit the extra endomorphisms of J_1(13) and perform a descent for a prime π above 19. They prove that multiplication by π is surjective on J(ℚ), forcing the finitely generated Mordell–Weil group to be finite. Hence

```plain text
rank J(ℚ) = 0,
J(ℚ) = J(ℚ)_tors ≅ ℤ/19ℤ.
```

This descent is a theorem about the abelian surface and its Galois cohomology. It does not use the assertion that every rational point of the curve is a cusp.

### The rational-point conclusion

Only after the group calculation does one combine it with the geometric statement that the Abel–Jacobi image of the curve intersects the rational torsion subgroup only in the six cusp classes. That yields the rational-point theorem.

This logical order is explicit in:

- Mazur–Tate, Points of order 13 on elliptic curves, Inventiones Mathematicae 22 (1973), 41–49;

- Snowden, Lecture 22: 13 torsion, especially the separate sections on Ogg's torsion calculation, the image of X in J, and the later rank-zero descent.

Therefore using J(ℚ) ≅ ℤ/19ℤ to prove specialization injectivity is not circular.

## What does not suffice

The following weaker facts do not prove the required group theorem by themselves:

- The existence of the cuspidal subgroup of order 19 gives only a lower bound.

- #J(𝔽₅)=19 controls rational torsion through reduction, but does not rule out positive Mordell–Weil rank.

- A numerical analytic-rank computation does not become a Lean theorem without a proved analytic-rank-to-algebraic-rank result.

- “BSD predicts rank zero” is not a proof. In fact Ogg explicitly observed that BSD predicts the answer; Mazur–Tate supplied an unconditional descent.

A modern modular/Kolyvagin route could also be logically independent, but it would introduce far more infrastructure than the fixed Mazur–Tate descent.

# 3. The reduction kernel at (p=2)

## The correct general statement

Let A/ℚ_p be an abelian variety and let 𝒜/ℤ_p be its Néron model. The kernel

```plain text
A(ℚ_p) = 𝒜(ℤ_p) → 𝒜(𝔽_p)
```

is the formal-neighborhood subgroup A₁(ℚ_p). It is a pro-(p) group. Consequently its finite torsion is (p)-primary, and reduction is injective on torsion of order prime to (p).

This does not require semistable reduction. Néron models exist for abelian varieties over local fields, and the pro-(p) assertion comes from the smooth formal group near the identity.

Good reduction is needed only for the clean identification

```plain text
𝒜_𝔽p = the reduced abelian variety Ã,
𝒜(𝔽_p) = Ã(𝔽_p).
```

With bad reduction one must retain the full Néron special fiber, including its components. A map to the Jacobian of a singular naive curve model is not automatically the same map.

## The sextic at 2 is a bad model, not evidence of bad reduction of X_1(13)

For

```plain text
f(X)=X⁶+4X⁵+6X⁴+2X³+X²+2X+1,
```

one has in 𝔽₂[X]

```plain text
f(X) = X⁶+X²+1 = (X³+X+1)²,
f'(X)=0.
```

Therefore the literal special fiber

```plain text
Y² = f(X)
```

is singular/nonreduced in characteristic 2. This shows only that completing the square and then reducing was the wrong integral operation at 2.

The modular curve X_1(13) has a smooth proper model over ℤ[1/13]; hence it, and its Jacobian, have good reduction at 2. In characteristic 2 one should use a generalized hyperelliptic equation

```plain text
Y² + h(X)Y = g(X),
```

not the completed-square sextic.

The connector-visible repository file

```plain text
FLT/Assumptions/MazurProof/N13VerticalGraphJacobian.lean
```

is consistent with exactly this correction. It fixes the prime 2 and constructs the curve equation in the form

```plain text
y² + hPoly(x)·y - rhsPoly(x),
```

through N13GeneralizedMumfordIntegral, rather than reducing the pure sextic directly.

## What still has to be proved in Lean

The Néron argument proves class_eq_iff only after establishing a commuting square:

```plain text
rational Picard/Jacobian class  --reduction--> Néron special class
          |                                      |
          | class constructor                    | comparison
          v                                      v
     genericClass                           specialClass
```

The actual code-level audit must locate the theorem asserting that specialClass L is the reduction of the generic divisor class attached to L. If the codomain is a graph Jacobian, a quotient Picard group, or a Mumford-coordinate class group, one also needs an injective comparison with the Néron special fiber—or a direct finite proof of equality reflection in that codomain.

So the (p=2) mathematics is sound. The possible hidden gap is not semistability; it is the comparison between the repository's explicit special-class object and the canonical reduction map.

# 4. The (p=5) alternative

## The displayed model itself is smooth modulo 5

A direct exact computation gives

```plain text
gcd(f mod 5, f' mod 5) = 1,
Disc(f) ≡ 1 mod 5.
```

The derivative being nonzero as a polynomial would not by itself be enough; the required condition is coprimality of f and f'. Here that stronger condition holds.

Because the polynomial has degree 6, squarefree reduction, and leading coefficient 1 in odd characteristic, the standard projective hyperelliptic model has good reduction at 5.

## Independent point-count certificate

Exact enumeration gives

```plain text
#X(𝔽₅)   = 6,
#X(𝔽₂₅) = 12.
```

For a genus-two curve,

```plain text
#J(𝔽_q) = -q + 1/2·#X(𝔽_{q²}) + 1/2·#X(𝔽_q)².
```

Therefore

```plain text
#J(𝔽₅) = -5 + 12/2 + 6²/2 = 19.
```

This independently confirms the project computation.

## What this proves

If one already has

```plain text
J(ℚ) ≅ ℤ/19ℤ,
```

then reduction at 5 is injective, because its kernel has only 5-primary torsion while J(ℚ) is 19-primary. Since the source and target both have 19 elements, the reduction map is in fact an isomorphism.

The equality #J(𝔽₅)=19 is stronger than needed for injectivity once the source is known to be ℤ/19ℤ; it gives a very clean finite consistency check.

## What this does not prove

It does not prove rank zero. If J(ℚ) had positive rank, a homomorphism from the infinite group J(ℚ) to the finite group J(𝔽₅) would necessarily have a large kernel. Thus

```plain text
#J(𝔽₅)=19 + a rational 19-torsion point
```

proves the prime-to-5 rational torsion is exactly the known order-19 subgroup, but does not show that every rational Jacobian point is torsion.

The Mazur–Tate descent, or an equivalent rank-zero theorem, is still required.

# 5. Why (p=5) is not a wholesale replacement for (p=2)

The N13 endpoint contains FirstJetDoublingCompatibility. Its role is tied to reduction in characteristic 2: the differential of multiplication by 2 vanishes modulo 2, and the centered doubling identities become second-order ideal statements. The mirrored N13 integral code is explicitly specialized to prime 2.

At (p=5), multiplication by 2 has nonzero differential. A first-jet argument designed around characteristic 2 will not transfer merely by changing the finite field.

Therefore the recommended separation is:

- retain (p=2) for the local first-jet/centered-doubling endpoint;

- use (p=5) as an independent and especially clean certificate for finite-field point counts, torsion bounds, and the global class-group model;

- prove that the (p=2) specialClass is genuine reduction from J(ℚ), then invoke prime-to-2 injectivity using the order-19 theorem.

Switching the entire endpoint to (p=5) would likely discard the very characteristic-2 feature that FirstJetDoublingCompatibility is exploiting.

# 7. A potentially easier finite-cyclic Lean proof

If the development already represents the generic and special Picard groups explicitly as cyclic groups of order 19, general Néron-model formalization may be unnecessary.

Suppose one has

```javascript
G  ≃+ ZMod 19,
S₂ ≃+ ZMod 19,
red2 : G →+ S₂.
```

Because 19 is prime, any nonzero homomorphism ZMod 19 →+ ZMod 19 is injective. It is enough to compute that one cusp-difference generator has nonzero reduction—or, better, that it reduces to the chosen special generator.

This yields:

```plain text
red2 ≠ 0
⇒ ker(red2)=⊥
⇒ red2 is injective
⇒ class_eq_iff.
```

This is likely the highest-return formalization route if the 283-file N13 infrastructure already supplies explicit class codes. It turns the final injectivity step into finite algebra rather than a new Néron-model library.

The deep theorem remains the identification of the rational Jacobian group with ZMod 19. But once that is present, the class-reflection proof can be tiny and computationally checkable.

A hybrid certificate is also possible:

1. prove or import the fixed-curve theorem J(ℚ) ≃+ ZMod 19;

1. compute #J(𝔽₂)=19 or #J(𝔽₅)=19;

1. compute the reduction of one cusp generator;

1. deduce injectivity by cyclic-prime group theory.

This avoids formalizing the general statement that a Néron reduction kernel is pro-(p), while remaining mathematically honest.
