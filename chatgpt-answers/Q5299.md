# 1. Database cross-check: the sextic is X_1(13)

The LMFDB modular-curve entry 13.168.2-13.b.2.2 for X_1(13) records the generalized hyperelliptic model

```plain text
Y² + (x³+x²+1)Y = -x⁵-x³+x²-x.                 (1)
```

In Magma coefficient-list notation this is

```javascript
HyperellipticCurve([
  [0,-1,1,-1,0,-1],
  [1,0,1,1]
]);
```

where Magma interprets a generalized hyperelliptic curve as Y²+h(x)Y=f(x); see the Magma hyperelliptic-curve handbook.

Complete the square by setting

```plain text
w = 2Y + x³+x²+1.
```

Then (1) becomes

```plain text
w² = f_std(x),

f_std(x) = x⁶-2x⁵+x⁴-2x³+6x²-4x+1.            (2)
```

Now let

```plain text
v = -1/x,
u = -w/x³ = v³w.
```

A direct polynomial identity gives

```plain text
v⁶ f_std(-1/v)
  = v⁶+4v⁵+6v⁴+2v³+v²+2v+1
  = f_Lean(v).                                  (3)
```

Consequently

```plain text
u² = f_Lean(v),
```

which is exactly the sextic used in C13SexticEq:

```plain text
u² = v⁶+4v⁵+6v⁴+2v³+v²+2v+1.                  (4)
```

So the Lean sextic is not an unrelated genus-two curve. It is the standard X_1(13) curve after completing the square and applying the fractional-linear coordinate change v=-1/x.

The polynomial discriminant is

```plain text
Disc(f_Lean) = -692224 = -2¹²·13².
```

Therefore the pure sextic (4) is a smooth integral hyperelliptic model at every odd prime other than 13, in particular at 3 and 5. At 2, completing the square is not an integral operation, and the reduction of (4) is singular; the generalized equation (1), or an equivalent characteristic-two model, must be used there. This is why the repository's integral N13 machinery uses a generalized equation of the form

```plain text
y² + h(x)y = rhs(x)
```

rather than naively reducing the completed-square sextic modulo 2.

# 2. Exact enumeration over 𝔽₉

Take

```plain text
𝔽₉ = 𝔽₃[t]/(t²+1),
```

so t²=-1=2. The field elements are

```plain text
0, t, 2t, 1, 1+t, 1+2t, 2, 2+t, 2+2t.
```

Reducing the sextic modulo 3 gives

```plain text
f(X)=X⁶+X⁵+2X³+X²+2X+1.
```

The complete evaluation and square-root table is:

```plain text
x        f(x)       y with y²=f(x)
---------------------------------------
0        1          1, 2
 t       2+t        none
2t       2+2t       none
1        2          t, 2t
1+t      1+2t       none
1+2t     1+t        none

2+t      1+2t       none
```

Thus there are exactly six affine solutions (x,y) among the 9·9=81 coordinate pairs.

Because the equation has even degree six and square leading coefficient 1, its smooth projective completion has two 𝔽₉-rational points at infinity. Hence

```plain text
#C(𝔽₉) = 6 + 2 = 8.
```

Your 𝔽₉ count is therefore correct.

For comparison, over 𝔽₃ there are four affine points and the same two rational points at infinity, so

```plain text
#C(𝔽₃)=6.
```

# 3. Correct Weil polynomial and Jacobian order

For a genus-two curve over 𝔽_q, write

```plain text
L_C(T)
 = 1-a₁T+a₂T²-q a₁T³+q²T⁴.
```

If

```plain text
N₁=#C(𝔽_q),
N₂=#C(𝔽_{q²}),
```

then

```plain text
a₁ = q+1-N₁,

a₂ = (N₂-q²-1+a₁²)/2.
```

The Jacobian order is obtained by evaluating at T=1:

```plain text
#J(𝔽_q)
 = L_C(1)
 = q²+1+a₂-(q+1)a₁.                            (5)
```

## At q=3

Using N₁=6 and N₂=8:

```plain text
a₁ = 3+1-6 = -2,

a₂ = (8-9-1+(-2)²)/2 = 1.
```

Therefore

```plain text
L_3(T)=1+2T+T²+6T³+9T⁴,

#J(𝔽₃)=L_3(1)=1+2+1+6+9=19.
```

The value 3 comes from using the wrong sign in (5):

```plain text
9+1+1+4(-2)=3.
```

The correct term is -(q+1)a₁, not +(q+1)a₁.

## At q=5

Using N₁=6 and N₂=12:

```plain text
a₁=0,
a₂=(12-25-1)/2=-7,

#J(𝔽₅)=25+1-7=19.
```

The sign error was invisible at 5 because a₁=0.

# 4. Could a Jacobian of order 19 reduce to a group of order 3?

Not for this curve at 3.

The sextic discriminant is prime to 3, so the displayed model has good reduction at 3. For an abelian variety with good reduction at a prime p, reduction is injective on torsion of order prime to p. Therefore

```plain text
J(ℚ)[19] ↪ J(𝔽₃).
```

If J(ℚ) ≅ ℤ/19ℤ, it follows immediately that 19 divides #J(𝔽₃). A value #J(𝔽₃)=3 would contradict the order-19 rational cuspidal subgroup; it could not be explained by a nontrivial reduction kernel, because the formal reduction kernel has only 3-primary finite torsion and cannot contain a nonzero point of order 19.

At a bad prime, reducing into the Jacobian of a naive singular equation can fail to represent the Néron specialization map, so one must be more careful about the target. That caveat is relevant to the completed-square equation at 2, but not at 3.

Hence the consistent picture is

```plain text
J_1(13)(ℚ) ≅ ℤ/19ℤ,
#J_1(13)(𝔽₃)=19,
#J_1(13)(𝔽₅)=19,
```

with prime-to-3 and prime-to-5 torsion reduction injective at both primes.

# 5. Consequences for the Lean N13 architecture

The equation C13SexticEq is safe as a rational curve model and as an integral model at odd primes p≠13. It should not be used as the characteristic-two special fiber without first undoing the completion of the square.

For regression protection, the project should record four small exact certificates:

```plain text
Disc(C13SexticPoly) = -2¹²·13²,
#C(𝔽₃)=6,
#C(𝔽₉)=8,
#J(𝔽₃)=19.
```

The last should be implemented through the explicit polynomial

```plain text
L_3(T)=1+2T+T²+6T³+9T⁴
```

or through formula (5), so that the sign convention is visible and cannot regress.

For the characteristic-two endpoint, retain the generalized integral model already reflected in the N13 graph-Jacobian files. The statements #J(𝔽₂)=19 and #J(𝔽₃)=19 refer to the same smooth curve, but at 2 the former must be computed from a smooth generalized model rather than from the singular reduction of (4).
