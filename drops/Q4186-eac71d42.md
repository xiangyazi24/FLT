# 2. Why a mod-5 contradiction is impossible

In `F_5`:

```text
x       1  2  3  4
x^2     1  4  4  1
x^3     1  3  2  4
```

Hence

```text
{ nonzero squares } = {1,4},
{ nonzero cubes   } = {1,2,3,4}.
```

More strongly, `x ↦ x^3` is an involutive permutation of `F_5^×`.

The possible right-hand sides are all nonzero:

```text
branch I,  5 ∣ e:  -2*f^2 ∈ {2,3},
branch I,  5 ∣ f:     e^2 ∈ {1,4},
branch II, 5 ∣ e:    -f^2 ∈ {1,4},
branch II, 5 ∣ f:   2*e^2 ∈ {2,3}.
```

Each of `D^3`, `-A^3`, and `A^3` ranges through all of `F_5^×` as the relevant unit ranges through `F_5^×`. Therefore there cannot be a residue-class case bash in which every case fails.

# 5. What the prime 3 actually gives

This section uses

```text
R(A,D) = D^3 + 3*A*D^2 - A^3,
P(A,D) = A*D*(A+D).
```

## 5.1 Modulo 3 forces `3 ∣ P`, but gives no contradiction

Modulo `3`,

```text
R(A,D) ≡ D^3 - A^3 ≡ D - A.
```

If none of `A,D,A+D` is divisible by `3`, then `A` and `D` are equal nonzero residues modulo `3`; hence

```text
R ≡ 0  (mod 3).
```

But then `e` and `f` are both units modulo `3`, so

```text
branch I:  e^2 - 2*f^2 ≡ 1 - 2 = 2  (mod 3),
branch II: 2*e^2 - f^2 ≡ 2 - 1 = 1  (mod 3),
```

both impossible. Therefore either branch implies

```text
3 ∣ A*D*(A+D).
```

By pairwise coprimality, exactly one of `A,D,A+D` is divisible by `3`, and exactly one of `e,f` is divisible by `3`. The surviving residues are then

```text
branch I:  R ≡ 1  (mod 3),
branch II: R ≡ 2  (mod 3).
```

This is useful bookkeeping, not a contradiction.

## 5.2 Modulo 9 still has survivors

The nonzero square classes modulo `9` are

```text
{1,4,7},
```

and the cubes of units modulo `9` are

```text
{1,8} = {1,-1}.
```

When exactly one of `A,D,A+D` is divisible by `3`:

```text
3 ∣ A       ==> R ≡  D^3 ∈ {1,8}  (mod 9),
3 ∣ D       ==> R ≡ -A^3 ∈ {1,8}  (mod 9),
3 ∣ A + D   ==> R ≡  A^3 ∈ {1,8}  (mod 9).
```

For the last line, write `S=A+D`; then

```text
R = S^3 - 3*A^2*S + A^3 ≡ A^3  (mod 9).
```

On the branch side, because exactly one of `e,f` is divisible by `3`:

```text
branch I right side  ∈ {1,4,7},
branch II right side ∈ {2,5,8}.
```

Thus modulo `9` merely sharpens the possibilities to

```text
branch I:  R ≡ 1  (mod 9),
branch II: R ≡ 8  (mod 9).
```

Both survive.

# 6. Even `Q_3`-local nonsolubility is unavailable for the coarse branches

The failure is not just that modulus `9` was too small. Each coarse branch has a genuine `3`-adic point.

## 6.1 Branch I

Set

```text
A=3, D=1.
```

Then

```text
P=A*D*(A+D)=12,
R=D^3+3*A*D^2-A^3=-17.
```

Impose `e*f=12`, put `y=f^2`, and set `e=12/f`. The branch-I equation becomes

```text
-17 = 144/y - 2*y,
```

or

```text
F_I(y) := 2*y^2 - 17*y - 144 = 0.
```

At `y=1`:

```text
F_I(1) = -159 ≡ 0  (mod 3),
F_I'(1) = -13 ≡ 2 ≠ 0  (mod 3).
```

Hensel's lemma gives a unique `y ∈ Z_3` with `y ≡ 1 (mod 3)` and `F_I(y)=0`. Such a `3`-adic unit is a square: apply Hensel again to `z^2-y` at `z=1`. Choose `f^2=y` and `e=12/f`. Then

```text
e*f=12,
e^2-2*f^2=-17=R.
```

Here `f` is a unit and `3 ∣ e`, exactly as required by the local divisibility pattern.

## 6.2 Branch II

Set

```text
A=3, D=2.
```

Then

```text
P=3*2*5=30,
R=2^3+3*3*2^2-3^3=17.
```

Again put `y=f^2` and `e=30/f`. The branch-II equation is equivalent to

```text
F_II(y) := y^2 + 17*y - 1800 = 0.
```

At `y=1`:

```text
F_II(1) = -1782 ≡ 0  (mod 3),
F_II'(1) = 19 ≡ 1 ≠ 0  (mod 3).
```

Hensel gives a root `y ≡ 1 (mod 3)`, it is a square in `Z_3^×`, and choosing `f^2=y`, `e=30/f` yields

```text

2*e^2-f^2=17=R.
```

Therefore neither coarse branch is `Q_3`-locally obstructed. In particular, no search modulo `3^N`, for any `N`, can prove the desired contradiction at the level of the hypotheses stated in the question.

A finer descent can split a coarse branch into additional global squareclasses, and an individual refined covering might then fail locally. That would be genuinely new information; it is not contained in the present `A,D,e,f` data.

# 7. The minimal additional ingredient

## 7.1 Point-specific minimal statement

Let `C` be the smooth projective `X_1(18)` model, let `J=Jac(C)`, let `P ∈ C(Q)` be the hypothetical point, and let `c` be the rational cusp having the same reduction modulo `5`. Put

```text
x = [P-c] ∈ J(Q).
```

The logically minimal extra arithmetic statement is an explicit prime-to-`5` annihilator:

```text
there exists n>0 with gcd(n,5)=1 and n*x=0.
```

Indeed:

1. `P` and `c` have the same reduction, so `x` reduces to `0` in `J(F_5)`.
2. At good reduction, reduction is injective on torsion of order prime to `5`.
3. Hence `x=0`.
4. The Abel-Jacobi map `C -> J`, based at `c`, is injective for a genus-`2` curve, so `P=c`, contradiction.

This is the exact seam to expose in Lean. It is weaker than computing every element of `J(Q)`.

## 7.2 Standard uniform source of that annihilator

A clean sufficient package is

```text
rank J(Q) = 0,
J(Q)[5^∞] = 0.
```

Mordell-Weil finite generation plus rank zero makes `J(Q)` finite. Absence of rational `5`-torsion implies its torsion order is prime to `5`; if an element had order divisible by `5`, a suitable multiple would have exact order `5`.

The rank-zero assertion is the genuinely global part. In the standard approach it comes from a `2`-descent on the genus-`2` Jacobian, followed by the finite torsion/reduction check. A second good prime may be useful to bound the torsion and verify `J(Q)[5]=0`, but that second-prime count does **not** replace the rank-zero descent.

A schematic Lean endpoint is:


The declaration names are schematic; the mathematical dependency is the important part.

## 7.3 If avoiding Jacobians

An integer infinite descent must supply a map

```text
(A,D,e,f)  |->  (A',D',e',f')
```

that preserves the full branch equations and coprimality and strictly decreases a positive height such as

```text
max(A,D),  A+D,  or  |A*D*(A+D)|.
```

The present factorization into branches does not itself provide such a map. It is a parametrization in `Z[sqrt(-2)]`, not yet an infinite descent. Therefore one should not formalize a claimed descent until the smaller quadruple and the strict height inequality are explicit.
