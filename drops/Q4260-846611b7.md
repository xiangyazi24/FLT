# Fixed-instance genus-2 Jacobian arithmetic for X_1(18)

## Executive conclusion

For the curve

```text
C : y^2 = f(x),
f = x^6 + 4*x^5 + 10*x^4 + 10*x^3 + 5*x^2 + 2*x + 1,
```

the smallest useful Lean development is **not** a general hyperelliptic-geometry library. It is a fixed-instance, certificate-driven arithmetic layer with three levels:

1. a concrete generalized Mumford datum `(u,v,nInf)` and a decidable validity/reducedness predicate;
2. Cantor composition plus a fixed even-degree reduction certificate checker;
3. a finite table of the 21 torsion representatives, whose polynomial identities are checked by `ring`/`norm_num`, with the abstract group structure transported from `ZMod 21`.

A later semantic layer may identify these normal forms with the actual divisor-class Jacobian. Mathlib currently has no hyperelliptic curve, divisor, Picard group, or Jacobian API, so that identification is genuinely new infrastructure.

There is one important correction to the premise. The curve has no rational **Weierstrass** point because the sextic has no rational root, but its monic even-degree model has two rational, non-Weierstrass points at infinity:

```text
∞+ : y/x^3 -> +1,
∞- : y/x^3 -> -1.
```

These two points are exactly why a third integer coordinate is required.

The key fixed-instance identity is

```text
q = x^3 + 2*x^2 + 3*x - 1,
f = q^2 + 8*x.
```

It makes the real/even-degree reduction completely explicit and produces a hand-computable 21-cycle generated by

```text
delta = [∞+ - ∞-].
```

The 21 representative table appears in section 8.

# 3. Generalized Mumford data

Choose `∞-` as the base point. A triple `(u,v,nInf)` represents

```text
D_aff(u,v) - deg(u)*∞- + nInf*(∞+ - ∞-).
```

Here `D_aff(u,v)` is the affine effective divisor cut out by

```text
u(x)=0,
y=v(x).
```

The integer coordinate is allowed to be arbitrary in raw/intermediate data. A canonical reduced representative has `nInf >= 0` and

```text
deg(u) + nInf <= 2.
```

This is the genus-2 specialization of the standard real-hyperelliptic representation.

## 3.1 Data type

```lean
structure MumfordData where
  u : QX
  v : QX
  nInf : ℤ
deriving DecidableEq, Repr

namespace MumfordData

protected def zero : MumfordData :=
  ⟨1, 0, 0⟩

instance : Zero MumfordData :=
  ⟨MumfordData.zero⟩

protected def delta : MumfordData :=
  ⟨1, 0, 1⟩
```

## 3.2 Validity predicate

For a fixed field, using remainder equalities is easier to compute than existential divisibility.

```lean
def IsSemireduced (D : MumfordData) : Prop :=
  D.u.Monic ∧
  D.u ≠ 0 ∧
  D.v % D.u = D.v ∧
  (f18 - D.v^2) % D.u = 0

def weight (D : MumfordData) : ℤ :=
  (D.u.natDegree : ℤ) + D.nInf

def IsReduced (D : MumfordData) : Prop :=
  D.IsSemireduced ∧
  0 ≤ D.nInf ∧
  D.weight ≤ 2
```

Because `u` is monic, `v % u = v` is equivalent to the usual canonical condition `deg v < deg u`, including the identity case `u=1`, where it forces `v=0`.

An equivalent proposition-oriented predicate is:

```lean
def IsSemireduced' (D : MumfordData) : Prop :=
  D.u.Monic ∧
  (D.v = 0 ∨ D.v.natDegree < D.u.natDegree) ∧
  D.u ∣ f18 - D.v^2
```

Prove once that these agree for monic `u`.

## 3.3 Certificate form

For fixed table entries, avoid asking tactics to solve existential divisibility. Store the quotient explicitly.

```lean
structure ValidCert (D : MumfordData) where
  uMonic : D.u.Monic
  uNeZero : D.u ≠ 0
  vCanonical : D.v % D.u = D.v
  quotient : QX
  factorization : f18 - D.v^2 = D.u * quotient

lemma ValidCert.isSemireduced {D : MumfordData} (h : ValidCert D) :
    D.IsSemireduced := by
  refine ⟨h.uMonic, h.uNeZero, h.vCanonical, ?_⟩
  rw [h.factorization, EuclideanDomain.mod_eq_zero]
  exact dvd_mul_right _ _
```

This makes every concrete table proof a `ring` computation.

# 4. Negation

For the convention `y=v`, affine conjugation is `v -> -v`. The raw inverse formula is

```text
(u,v,n) |-> (u,-v mod u,-deg(u)-n).
```

Indeed, for the degree-`d` affine divisor,

```text
D(u,v) + D(u,-v) ~ d*∞+ + d*∞-.
```

Compile-shaped definition:

```lean
def negRaw (D : MumfordData) : MumfordData :=
  { u := D.u
    v := (-D.v) % D.u
    nInf := -(D.u.natDegree : ℤ) - D.nInf }
```

`negRaw D` is generally not reduced. It must be passed through the even-degree reduction procedure.

# 5. Cantor composition

## 5.1 Three-term extended gcd

For inputs `u1,u2,v1+v2`, Cantor composition needs

```text
d = s1*u1 + s2*u2 + s3*(v1+v2).
```

This is obtained by two uses of Mathlib's extended Euclidean algorithm.

```lean
structure Bezout3 (a b c : QX) where
  d s1 s2 s3 : QX
  eqn : d = s1*a + s2*b + s3*c
  dvdA : d ∣ a
  dvdB : d ∣ b
  dvdC : d ∣ c

noncomputable def bezout3 (a b c : QX) : Bezout3 a b c := by
  let g := EuclideanDomain.gcd a b
  let ea := EuclideanDomain.gcdA a b
  let eb := EuclideanDomain.gcdB a b
  let d := EuclideanDomain.gcd g c
  let eg := EuclideanDomain.gcdA g c
  let ec := EuclideanDomain.gcdB g c
  refine
    { d := d
      s1 := eg * ea
      s2 := eg * eb
      s3 := ec
      eqn := ?_
      dvdA := ?_
      dvdB := ?_
      dvdC := ?_ }
  · rw [EuclideanDomain.gcd_eq_gcd_ab g c]
    rw [EuclideanDomain.gcd_eq_gcd_ab a b]
    ring
  · exact (EuclideanDomain.gcd_dvd_left g c).trans
      (EuclideanDomain.gcd_dvd_left a b)
  · exact (EuclideanDomain.gcd_dvd_left g c).trans
      (EuclideanDomain.gcd_dvd_right a b)
  · exact EuclideanDomain.gcd_dvd_right g c
```

The divisibility directions in the last three fields should be checked while implementing; if Lean chooses the opposite transitivity orientation, use explicit `rcases` witnesses. The mathematical content and API names are exact.

## 5.2 Composition formula

For

```text
D1=(u1,v1,n1),
D2=(u2,v2,n2),
```

let

```text
d = gcd(u1,u2,v1+v2)
```

with Bézout coefficients `s1,s2,s3`. Set

```text
u0 = u1*u2/d^2,
N  = s1*u1*v2 + s2*u2*v1 + s3*(v1*v2+f),
v0 = (N/d) mod u0.
```

The infinity coordinate is

```text
n0 = n1+n2+deg(d).
```

The `+deg(d)` is essential. Each cancelled conjugate pair is linearly equivalent to `∞+ + ∞-`, which contributes one copy of `∞+ - ∞-` in the chosen base-point convention.

Since generic Euclidean gcds and quotients may be unit-scaled, monicize `u0`.

```lean
noncomputable def monicize (p : QX) : QX :=
  if hp : p = 0 then 0 else C p.leadingCoeff⁻¹ * p

noncomputable def composeRaw (D1 D2 : MumfordData) : MumfordData :=
  let b := bezout3 D1.u D2.u (D1.v + D2.v)
  let u0 := (D1.u * D2.u) / (b.d^2)
  let u := monicize u0
  let numer :=
      b.s1 * D1.u * D2.v
    + b.s2 * D2.u * D1.v
    + b.s3 * (D1.v * D2.v + f18)
  let v := ((numer / b.d) % u)
  { u := u
    v := v
    nInf := D1.nInf + D2.nInf + (b.d.natDegree : ℤ) }
```

# 6. Even-degree reduction

This is the genuinely delicate part. The fixed curve makes it small.

## 6.1 Orders at infinity

For a cubic-or-lower polynomial `w`, define the orders of `y-w` at the two infinities by comparing `w` with `q18`.

```lean
def ordPlus (w : QX) : ℤ :=
  if q18 - w = 0 then 2
  else -((q18 - w).natDegree : ℤ)

def ordMinus (w : QX) : ℤ :=
  if q18 + w = 0 then 2
  else -((q18 + w).natDegree : ℤ)
```

For `deg w <= 3`, prove the fixed infinity identity

```lean
lemma ordPlus_add_ordMinus
    (w : QX)
    (hwdeg : w.natDegree ≤ 3)
    (hneq : f18 - w^2 ≠ 0) :
    ordPlus w + ordMinus w
      = -((f18 - w^2).natDegree : ℤ) := by
  -- New fixed-degree proof.
  -- Split w=q18, w=-q18, and the generic case.
  -- Use f18=q18^2+8X.
```

This lemma is the polynomial substitute for a local-coordinate development at infinity.

## 6.2 Choosing a lift of v

Reduction may replace `v` by any congruent polynomial modulo `u`. To move toward `∞+`, choose the polynomial congruent to `v` that is closest to `q18`:

```lean
def liftPlus (D : MumfordData) : QX :=
  q18 - ((q18 - D.v) %ₘ D.u)

def liftMinus (D : MumfordData) : QX :=
  -q18 - ((-q18 - D.v) %ₘ D.u)
```

For monic `u`, prove:

```lean
lemma liftPlus_mod (D : MumfordData) (hu : D.u.Monic) :
    liftPlus D %ₘ D.u = D.v %ₘ D.u := by
  -- modByMonic_add_div / ring

lemma liftMinus_mod (D : MumfordData) (hu : D.u.Monic) :
    liftMinus D %ₘ D.u = D.v %ₘ D.u := by
  -- same
```

`liftPlus` is used when the infinity weight is too large; `liftMinus` is used when it is too small.

## 6.3 One reduction step

Suppose `w ≡ v mod u` and `u | f-w^2`. Define

```text
u0 = (f-w^2)/u,
u' = monicize(u0),
v' = -w mod u',
n' = n - deg(u') - ordPlus(w).
```

The infinity formula follows from

```text
div(y-w) = D(u,w) + D(u0,w)
           + ordPlus(w)*∞+ + ordMinus(w)*∞-.
```

Compile-shaped definition:

```lean
noncomputable def reduceOneWith
    (D : MumfordData) (w : QX) : MumfordData :=
  let u0 := (f18 - w^2) /ₘ D.u
  let u' := monicize u0
  let v' := (-w) %ₘ u'
  { u := u'
    v := v'
    nInf := D.nInf - (u'.natDegree : ℤ) - ordPlus w }
```

## 6.4 Reduction certificate

```lean
structure ReductionCert (In Out : MumfordData) where
  lift : QX
  liftDegree : lift.natDegree ≤ 3
  liftCongruent : lift %ₘ In.u = In.v
  quotient : QX

  quotientNeZero : quotient ≠ 0

  outAssociated : Associated Out.u quotient
  outV : Out.v = (-lift) %ₘ Out.u
  outN :
    Out.nInf = In.nInf - (Out.u.natDegree : ℤ) - ordPlus lift
  outValid : Out.IsSemireduced
```

The semantic theorem, which is new, should be isolated:

```lean
theorem ReductionCert.sameClass
    {In Out : MumfordData}
    (h : ReductionCert In Out) :
    MumfordClass In = MumfordClass Out := by
  -- Uses the principal divisors of y-h.lift and of h.quotient.
```

Until `MumfordClass` exists, use `ReductionCert` merely as a checked transition object.

## 6.5 Well-founded total reduction

For the fixed application, do not start with a general recursive algorithm. Define a certified chain:

```lean
inductive ReductionChain : MumfordData → MumfordData → Prop
  | done (D) : D.IsReduced → ReductionChain D D
  | step {A B C} :
      ReductionCert A B → ReductionChain B C → ReductionChain A C
```

This is sufficient for every torsion-table calculation.

A later deterministic reducer may use

```text
if weight>2, use liftPlus;
if nInf<0, use liftMinus;
otherwise stop.
```

Its termination measure should be a lexicographic pair consisting of affine degree and distance of `weight` from `[0,2]`. Proving totality is new infrastructure and is not required before the finite table lands.

# 7. Six fixed reduction identities

All reductions in the 21-cycle use only the following six lifts.

```lean
def w0 : QX := q18

def wA : QX := q18 + C 2

def wB : QX := q18 - C 4 * X

def wC : QX := q18 - C 2 * X + C 2

def wD : QX := q18 - C 2 * X

def wE : QX := q18 + C 4
```

The complete algebraic bank is:

```lean

  simp [f18, q18, wA]
```

## 8.1 First divisor relations

The identity `f=q^2+8x` gives two immediate principal-divisor relations:

```text
div(y+q) = (0,1) + 2*∞- - 3*∞+,
div(y-q) = (0,-1) + 2*∞+ - 3*∞-.
```

Hence

```text
[(0,1)-∞-]  =  3*delta,
[(0,-1)-∞-] = -2*delta.
```

This explains `D3=(x,1,0)` and `D19=(x,-1,0)`.

```lean
      D11,D12,D13,D14,D15,D16,D17,D18,D19,D20] at h ⊢
```

A Boolean/table formulation may close this with `native_decide`. The polynomial arithmetic itself should remain proof-by-certificate, because Mathlib's generic polynomial division definitions are marked noncomputable.

# 9. Transporting the finite group structure

Before the full Jacobian semantics exists, define the proved torsion object as `ZMod 21` and attach the table as an interpretation.

```lean
  -- finite table / certificates
```

the additive group laws are inherited from `ZMod 21`; do not prove associativity by expanding Cantor formulas 441 times.

If a fully computational fixed addition table is desired, define

and prove its finite laws by `decide`/`native_decide`. The bridge from index addition to Mumford arithmetic is the certificate theorem `torsionNormalForm_add`.

# 10. Two-torsion

The displayed torsion subgroup has no nonzero 2-torsion because multiplication by 2 is injective on `ZMod 21`.

```lean
lemma two_mul_eq_zero_iff (a : ZMod 21) :
    2 • a = 0 ↔ a = 0 := by
  constructor
  · intro h
    have h2 : IsUnit (2 : ZMod 21) := by native_decide
    exact h2.mul_left_cancel (by simpa using h)
  · rintro rfl
    simp
```

To prove that the **whole rational Jacobian** has no other 2-torsion, a separate global statement is needed. Do not use the false shortcut “the sextic is irreducible, therefore `J[2](ℚ)=0`.” For an even sextic, a rational 2-torsion class is a Galois-invariant even subset of the six branch points modulo complement; an irreducible sextic can still admit a Galois-stable 3+3 block system modulo complement.

For this curve, close global 2-torsion by one of:

1. the explicit 2-descent already planned for `324.a.648.1`;
2. a finite Galois-action certificate showing no nonzero fixed vector in
   `F_2^6 / <(1,1,1,1,1,1)>`;
3. a completed finite torsion exhaustion proving every torsion class is in the 21-table.

This is arithmetic beyond the foundational Mumford layer.

# 11. Semantic bridge options

There are two reasonable implementation routes.

## Route A: actual divisors

Build only the fixed projective curve and the minimum divisor theory required to interpret the certificates:

```lean
structure Point18
inductive Place18
abbrev Divisor18 := Place18 →₀ ℤ

def principalXSub (a : AlgebraicClosure ℚ) : Divisor18

def principalYSub (w : QX) : Divisor18

def Principal18 : AddSubgroup Divisor18

def PicZero18 := {D : Divisor18 // degree D = 0} ⧸ Principal18
```

Then define

```lean
def MumfordClass : MumfordData → PicZero18
```

and prove:

```lean
MumfordClass_composeRaw
ReductionCert.sameClass
MumfordClass_negRaw
reduced_unique
```

This is mathematically clean but is the largest infrastructure task.

## Route B: certified presentation

Define an equivalence relation generated by the exact Cantor and reduction certificates:

```lean
inductive MumfordRel : MumfordData → MumfordData → Prop
  | reduction {A B} : ReductionCert A B → MumfordRel A B
  | composition {A B C} : ComposeCert A B C → ...
  | refl | symm | trans
```

Then use the quotient as a computationally presented group. Later construct a homomorphism to the true Picard group and prove it injective on reduced representatives.

For the FLT application, Route B gets the torsion table and all finite computations into Lean much sooner.

# 13. Build order

# 14. Main cautions for Codex

- Do not model this as an odd-degree curve with one point at infinity.
- Do not drop `nInf`.
- Do not install a global group instance on raw/reduced triples before proving normalization correctness.
- Do not use irreducibility of `f` alone as a proof of trivial rational 2-torsion.
- Do not rely on simplification of generic gcd normalization; use explicit `ComposeCert` fields.
- Prefer `%ₘ` and `/ₘ` when the divisor is known monic.
- Keep the convention `u | f-v^2` and `y=v` consistent; changing to `y=-v` reverses several table signs.
- The table above is hand-derived from six exact polynomial identities. It should be machine-checked in Lean before being used as a theorem, but no unknown Jacobian arithmetic remains in the table itself.
