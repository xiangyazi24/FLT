def shortCubicRootFactor (A B e t : ℝ) : ℝ :=
  t ^ 2 + t * e + e ^ 2 + A * (t + e) + B

    {A B e t : ℝ} (hroot : shortCubic A B e = 0) :
    shortCubic A B t = (t - e) * shortCubicRootFactor A B e t := by

## D. Audit of the current `sqrt` junk extension

The junk extension is acceptable **only after** the theorem has `hposRight` and every improper integral is over a set contained in `Ioi e`. On that domain the cubic is positive, so `Real.sqrt` is the intended positive square root and the negative-value behavior is irrelevant.

I would not switch to

```lean
if 0 < shortCubic A B t then (Real.sqrt (shortCubic A B t))⁻¹ else 0
```

for the main definitions. It creates extra `if` splits in continuity and interval-integral proofs. Keep the simple definition and add local simp/positivity lemmas:

```lean
theorem shortEllipticIntegrand_pos
    {A B e t : ℝ}
    (hposRight : ∀ ⦃x : ℝ⦄, e < x → 0 < RealTopology.shortCubic A B x)
    (ht : e < t) :
    0 < RealTopology.shortEllipticIntegrand A B t := by
  unfold RealTopology.shortEllipticIntegrand
  exact inv_pos.mpr (Real.sqrt_pos.mpr (hposRight ht))

theorem shortEllipticIntegrand_ne_zero
    {A B e t : ℝ}
    (hposRight : ∀ ⦃x : ℝ⦄, e < x → 0 < RealTopology.shortCubic A B x)
    (ht : e < t) :
    RealTopology.shortEllipticIntegrand A B t ≠ 0 :=
  ne_of_gt (shortEllipticIntegrand_pos hposRight ht)
```

If `hposRight` is unavailable, the current integral over `Ioi e` is not just a simplification hazard; it is the wrong coordinate for a left positive-slope root. The fix is root selection, not an `if`.
