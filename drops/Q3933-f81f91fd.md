# Q3933 — wiring `scratch.ObstructionN14` into the FLT Lake build

The cleanest short-term wiring is **option 2 plus a thin option-3 bridge**:

- do **not** move the 1924-line proof yet;
- make the `scratch` module tree visible to Lake;
- then import `scratch.ObstructionN14` from the FLT-side file that replaces the axiom, or from a small FLT-side bridge file if that avoids clutter.

So the essential Lake change is in `lakefile.toml`.

```toml
[[lean_lib]]
name = "FLT"
globs = ["FLT", "FermatsLastTheorem", "scratch.+"]
```

Use `scratch.+`, not plain `scratch`:

- `scratch` means only the module `scratch`, i.e. essentially `scratch.lean`;
- `scratch.+` means the submodules under `scratch/`, such as `scratch.ObstructionN14`, `scratch.SquareStep014`, and `scratch.FourSquaresAP`;
- `scratch.*` is also acceptable only if there is, or you want Lake to build, a root module `scratch.lean` as well as the submodules.

Since the file is `scratch/ObstructionN14.lean` and its imports are also under `scratch/`, `scratch.+` is the minimal correct glob.

## Why this is cleaner than moving the proof

Moving `ObstructionN14.lean` and its dependencies into `FLT/` is fine as a later cleanup, but it is more invasive: imports change, paths change, and the large proof becomes part of the production namespace before you have decided on its final home.

Adding `scratch.+` to the existing `FLT` library keeps the proof exactly where it is and lets Lake build it from a clean checkout. Then an FLT file can depend on the theorem normally.

Creating a new file in `FLT/` that merely says `import scratch.ObstructionN14` is useful as an interface layer, but it is **not sufficient by itself** unless Lake also knows that `scratch.ObstructionN14` is a buildable local module. That is why the Lake glob is the real build-graph change.

## Replacing the axiom in `DescentBridgeN14.lean`

If `E_N14_AffineEquation` and `E_N14_DegenerateParameter` are defined in `DescentBridgeN14.lean`, the lowest-churn patch is to import the scratch proof directly in that file and replace the axiom by this theorem:

```lean
import scratch.ObstructionN14

-- keep the existing imports of FLT/Assumptions/MazurProof/DescentBridgeN14.lean too

-- existing definitions:
-- def E_N14_AffineEquation (u w : Q) : Prop :=
--   w^2 = u^3 + u^2 - 2*u
--
-- def E_N14_DegenerateParameter (u : Q) : Prop :=
--   u = -2 or u = 0 or u = 1

 theorem obstruction_curve_N14_points_degenerate :
    forall u w : Q, E_N14_AffineEquation u w -> E_N14_DegenerateParameter u := by
  intro u w h
  simpa [E_N14_AffineEquation, E_N14_DegenerateParameter] using
    obstruction_N14 u w h
```

In other words, replace

```lean
axiom obstruction_curve_N14_points_degenerate :
  forall u w : Q, E_N14_AffineEquation u w -> E_N14_DegenerateParameter u
```

with the theorem above.

If you want a separate FLT-facing bridge file, avoid an import cycle. A bridge file cannot import `DescentBridgeN14.lean` to get the definitions and then be imported back by `DescentBridgeN14.lean`. In that layout, first split the definitions into a defs-only file, for example:

```lean
-- FLT/Assumptions/MazurProof/DescentBridgeN14Defs.lean

-- keep whatever imports are needed for Q and the arithmetic notation

-- example only; keep the project's actual namespace if different

```

Then the bridge can be:

```lean
-- FLT/Assumptions/MazurProof/ObstructionCurveN14.lean
import scratch.ObstructionN14
```

and `DescentBridgeN14.lean` imports the bridge theorem instead of declaring the axiom.

## Proving `rank_zero_96a1` from `obstruction_N14`

The scratch theorem gives only the allowed `u` values. The stronger `rank_zero_96a1` also needs `w = 0`; that follows by substituting each allowed `u` into

```lean
w^2 = u^3 + u^2 - 2*u
```

because the right-hand side is `0` for `u = -2`, `u = 0`, and `u = 1`.

A typical replacement theorem is:

```lean
import Mathlib.Tactic
import scratch.ObstructionN14

 theorem rank_zero_96a1 :
    forall u w : Q,
      w^2 = u^3 + u^2 - 2*u ->
        (u = -2 ∧ w = 0) ∨ (u = 0 ∧ w = 0) ∨ (u = 1 ∧ w = 0) := by
  intro u w h
  have hu : u = -2 ∨ u = 0 ∨ u = 1 := obstruction_N14 u w h
  rcases hu with hu | hu | hu
  · subst u
    left
    refine ⟨by norm_num, ?_⟩
    have hw2 : w^2 = 0 := by
      nlinarith [h]
    exact sq_eq_zero_iff.mp hw2
  · subst u
    right
    left
    refine ⟨by norm_num, ?_⟩
    have hw2 : w^2 = 0 := by
      nlinarith [h]
    exact sq_eq_zero_iff.mp hw2
  · subst u
    right
    right
    refine ⟨by norm_num, ?_⟩
    have hw2 : w^2 = 0 := by
      nlinarith [h]
    exact sq_eq_zero_iff.mp hw2
```

You may not need the explicit `import Mathlib.Tactic` if the existing file already imports the tactic stack; it is included here to make the snippet self-contained.
