# Exact `padicValRat` proof of the formal doubling estimate

## Two corrections that are necessary in Lean

There are two small but essential points hidden by the usual paper notation.

First, Mathlib defines

```lean
padicValRat 2 (0 : ℚ) = 0
```

rather than \(+\infty\). Consequently, the literal statement

```lean
padicValRat 2 (z (2 • P)) ≥ padicValRat 2 (z P) + 1
```

is false when `2 • P = 0` and the totalized parameter has `z 0 = 0`. This is not a hypothetical edge case at \(p=2\): a nonzero rational two-torsion point can lie in the formal kernel. The correct theorem is either

```lean
z (2 • P) = 0 ∨
  padicValRat 2 (z P) + 1 ≤ padicValRat 2 (z (2 • P))
```

or the ordinary inequality together with the extra hypothesis

```lean
z (2 • P) ≠ 0.
```

The code below packages the first version as

```lean
def VAtLeast (k : ℤ) (q : ℚ) : Prop :=
  q = 0 ∨ k ≤ padicValRat 2 q
```

so zero behaves as though it had infinite valuation.

Second, when `padicValRat 2 z = 1`, a quadratic term has valuation \(2\), exactly the same valuation as `2*z`. Thus the complete higher-order tail is not necessarily of *strictly* larger valuation than `2*z`. One should not try to prove the lower bound by applying `padicValRat.add_eq_of_lt` to the whole tail. Cancellation between equal-valuation terms can occur, but it only raises the valuation. The correct lower-bound tool is

```lean
padicValRat.min_le_padicValRat_add
```

together with a separate zero case.

## Exact Mathlib lemma names

For `[Fact (Nat.Prime p)]`, the relevant declarations in the pinned Mathlib are:

```lean
padicValRat.add_eq_min
  (hqr : q + r ≠ 0) (hq : q ≠ 0) (hr : r ≠ 0)
  (hval : padicValRat p q ≠ padicValRat p r) :
  padicValRat p (q + r) = min (padicValRat p q) (padicValRat p r)

padicValRat.add_eq_of_lt
  (hqr : q + r ≠ 0) (hq : q ≠ 0) (hr : r ≠ 0)
  (hval : padicValRat p q < padicValRat p r) :
  padicValRat p (q + r) = padicValRat p q

padicValRat.min_le_padicValRat_add
  (hqr : q + r ≠ 0) :
  min (padicValRat p q) (padicValRat p r) ≤
    padicValRat p (q + r)

padicValRat.mul
  (hq : q ≠ 0) (hr : r ≠ 0) :
  padicValRat p (q * r) = padicValRat p q + padicValRat p r

padicValRat.pow
  (hq : q ≠ 0) :
  padicValRat p (q ^ n) = (n : ℤ) * padicValRat p q

padicValRat.div
  (hq : q ≠ 0) (hr : r ≠ 0) :
  padicValRat p (q / r) = padicValRat p q - padicValRat p r

padicValRat.self
  (hp : 1 < p) :
  padicValRat p (p : ℚ) = 1
```

## How to use this on an explicit doubling numerator

The cleanest interface is the theorem

```lean
formal_double_num_den
```

Suppose the explicit duplication calculation gives

```lean
z₂ = N / D
```

and a `ring` calculation gives

```lean
N = (2 * z + z ^ 2 * R) * D.
```

Then the complete application is:

```lean
have hz₂level : VAtLeast (v2 z + 1) z₂ :=
  formal_double_num_den
    hz                -- 1 ≤ v2 z
    hR                -- VAtLeast 0 R
    hD0               -- D ≠ 0
    hDunit            -- v2 D = 0
    hN                -- numerator identity, normally `by ring`
    hz₂formula        -- z₂ = N / D
```

If `z₂ ≠ 0`, recover the ordinary integer-valued inequality with

```lean
exact hz₂level.resolve_left hz₂_ne_zero
```

If the numerator is naturally written as a list of monomials rather than as `z^2 * R`, use

```lean
formal_double_num_den_of_tail
```

instead. It takes coefficients `c i`, degrees `degree i`, and the hypotheses

```lean
∀ i ∈ s, VAtLeast 0 (c i)
∀ i ∈ s, 2 ≤ degree i.
```

For a large expression such as `E21DoubleYNum`, it is often even easier not to normalize everything into powers of `z`. Bound each displayed term separately and combine the bounds with `VAtLeast.add` or `VAtLeast.sum`. For example, if

```lean
hx : VAtLeast vx x
hy : VAtLeast vy y
```

then the exact reusable patterns are

```lean
have hx6 : VAtLeast (6 * vx) (x ^ 6) := by
  simpa using hx.pow 6

have hxy : VAtLeast (vx + vy) (x * y) :=
  hx.mul hy

have hcxy : VAtLeast (vx + vy) ((c : ℚ) * (x * y)) := by
  have hc : VAtLeast 0 (c : ℚ) := VAtLeast.intCast c
  simpa using hc.mul hxy
```

After proving the same target lower bound for every term, use

```lean
exact h₁.add (h₂.add (h₃.add h₄))
```

or put the terms in a `Finset` and apply `VAtLeast.sum`. This is the direct solution to the “leading `x^6` plus terms divisible by higher powers of two” subproblem: do not try to make `padicValRat` simplify the entire expanded polynomial in one step.

## Pushing a point into the formal kernel with `4 • P`

Let

```lean
red : G →+ A
```

be the reduction homomorphism, where `A` is the reduced point group. If

```lean
hcard : Fintype.card A = 4,
```

then

```lean
four_smul_eq_zero_of_card_four hcard Q
```

proves `4 • Q = 0` for every `Q : A`. Internally this is exactly Lagrange via

```lean
AddGroup.exponent_dvd_card
```

followed by

```lean
AddMonoid.exponent_nsmul_eq_zero.
```

Therefore

```lean
four_smul_mem_reduction_ker_of_card_four red hcard P
```

proves

```lean
(4 : ℕ) • P ∈ red.ker.
```

If the formal kernel is a separately defined predicate with

```lean
hkernel : ∀ Q, FormalKernel Q ↔ red Q = 0,
```

then the final exact statement is

```lean
four_smul_mem_formal_kernel_of_card_four
  red FormalKernel hcard hkernel P
```

and its conclusion is

```lean
FormalKernel ((4 : ℕ) • P).
```

The only curve-specific infrastructure not supplied by this valuation file is the actual point-reduction homomorphism `red` and the proof identifying its kernel with the formal kernel. Once those are available, the exponent-four step is one application of the last theorem.

## Final point-level formulation

For a point `P` in the formal kernel, instantiate the numerator/denominator theorem with

```lean
z  := z P
z₂ := z ((2 : ℕ) • P).
```

The result is the formally correct statement

```lean
z ((2 : ℕ) • P) = 0 ∨
  padicValRat 2 (z P) + 1 ≤
    padicValRat 2 (z ((2 : ℕ) • P)).
```

If `2 • P ≠ 0` and the formal parameter is nonzero away from the identity, this immediately gives the ordinary requested inequality. If `2 • P = 0`, the doubled point is the identity, which belongs to every formal filtration level; the zero-aware disjunction is exactly the Lean representation of that fact.
