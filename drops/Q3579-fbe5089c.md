# Q3579: local chord derivative for the S6/S7 translation step

This is the local analytic/algebraic lemma I would put between the S6 infrastructure and the final `ThetaCandidateAdditive` patching argument.  The point is to keep the topology out of the proof: first prove a signed affine-coordinate derivative identity for the group law, then use the already checked `sigma_hasDerivAt_of_right` on each smooth branch.

## 1. Slope convention and addition formulas

Use the slope

\[
  m = \frac{y-b}{x-a}.
\]

This is the same real number as `(b-y)/(a-x)` when `x ≠ a`.  It is the slope of the affine line

\[
  Y = y + m(X-x)
\]

through `P=(x,y)` and `Q=(a,b)`.  For the short curve

\[
  y^2 = f(x), \qquad f(X)=X^3+A X^2+B X,
\]

the third intersection before reflection has x-coordinate

\[
  x_3 = m^2 - A - x - a.
\]

The group-law sum `R=P+Q` is the reflection of that third intersection, hence

\[
  y_3 = -\bigl(y + m(x_3-x)\bigr).
\]

Equivalently, if Mathlib uses the line in intercept form `Y = mX + c` with `c = y - m*x`, then

\[
  y_3 = -(m x_3 + c).
\]

This is the specialization of the general Weierstrass addition formula

\[
  X(P+Q)=m^2+a_1m-a_2-X(P)-X(Q),
\]

\[
  Y(P+Q)=-(Y(P)+m(X(P+Q)-X(P)))-a_1X(P+Q)-a_3,
\]

to `a₁=a₃=0`, `a₂=A`.  So for `shortW A B` this convention should be compatible with the usual `WeierstrassCurve.Affine.Point` addition formulas, up to definitional unfolding and perhaps a harmless slope name.

## 2. Minimal real lemma to expose

The cleanest interface is a signed branch lemma.  It does not mention `sqrt`; it only assumes a branch `u` through `P` whose derivative is the invariant-differential derivative `f'(x)/(2*y)`.  Then the upper branch is obtained with `u t = sqrt (f t)`, and the lower branch with `u t = -sqrt (f t)`.

For your repo, replace `sc` by `shortCubic A B`; the algebraic lemma should not depend on any topology file.  The only analytic input is the branch derivative

\[
  y' = \frac{f'(x)}{2y}, \qquad f'(x)=3x^2+2Ax+B.
\]

For the upper branch this follows from `y = sqrt (f x)` and `0 < f x`.  For the lower branch `y = -sqrt (f x)`, the derivative is still `f'(x)/(2*y)` because `y` is negative.

## 3. Polynomial identities to prove with `ring_nf` / `field_simp`

Let

\[
  D=x-a, \qquad
  S=x^2+xa+a^2+A(x+a)+B, \qquad
  F'=3x^2+2Ax+B.
\]

The useful identities are these:

1. Divided difference:

\[
  f(x)-f(a)=D S.
\]

2. Derivative versus divided difference:

\[
  F'=S+D(2x+a+A).
\]

3. Slope numerator:

\[
  mD=y-b.
\]

4. Chord-through-`Q` identity:

\[
  m(y+b)=S.
\]

This follows by clearing `D`:

\[
  (y-b)(y+b)=y^2-b^2=f(x)-f(a)=DS.
\]

5. The key differential identity:

\[
  F'-2ym = D(x-x_3).
\]

A Lean-friendly derivation is

\[
  2ym=m(y+b)+m(y-b)=S+m^2D,
\]

so

\[
  F'-2ym=(S+D(2x+a+A))-(S+m^2D)
          =D(2x+a+A-m^2)=D(x-x_3).
\]

6. If `y' = F'/(2y)`, then the slope derivative is

\[
  m' = \frac{y'D-(y-b)}{D^2}
     = \frac{y'-m}{D}
     = \frac{x-x_3}{2y}.
\]

7. Therefore

\[
  x_3' = 2mm'-1
        = \frac{m(x-x_3)-y}{y}
        = -\frac{y+m(x_3-x)}{y}
        = \frac{y_3}{y}.
\]

This final identity is exactly `chord_deriv_identity_algebra` above.

The most useful one-shot cleared-denominator check is:

\[
  2m\frac{(F'/(2y))D-(y-b)}{D^2}-1=\frac{y_3}{y}.
\]

With assumptions `hy : y^2=f x`, `hb : b^2=f a`, `hy0 : y≠0`, `hD : D≠0`, `field_simp [hD, hy0]` reduces it to

\[
  F'D+b^2-y^2-D^2(A+2x+a)=0,
\]

and then `rw [hy, hb]` followed by `ring_nf [f]` closes it.

Also prove once, because it is useful for branch selection of `thetaCandidate`:

\[
  f(X)-\bigl(y+m(X-x)\bigr)^2=(X-x)(X-a)(X-x_3).
\]

Setting `X=x_3` gives

\[
  y_3^2=f(x_3).
\]

Then if `y_3>0`, `Real.sqrt (f x_3)=y_3`; if `y_3<0`, `Real.sqrt (f x_3)=-y_3`.

## 4. How this plugs into `thetaCandidate`

On the upper branch, `theta(P(x)) = -sigma x`, and the checked lemma gives

\[
  \frac{d}{dx}\theta(P(x))=-\sigma'(x)=\frac{1}{\sqrt{f(x)}}=\frac1y.
\]

For `R(x)=(x_3(x),y_3(x))`, on a smooth upper branch of `R`,

\[
  \frac{d}{dx}\theta(R(x))
  = -\sigma'(x_3)x_3'
  = \frac{x_3'}{y_3}
  = \frac1y.
\]

On a smooth lower branch of `R`, `theta(R)=sigma x_3` and `sqrt(f x_3)=-y_3`, so again

\[
  \frac{d}{dx}\theta(R(x))
  = \sigma'(x_3)x_3'
  = \frac{x_3'}{y_3}
  = \frac1y.
\]

Thus the real representative of

\[
  \theta(R(x))-\theta(P(x))-\theta(Q)
\]

has derivative zero on every interval where the same formulas for `theta` apply.  The AddCircle-valued defect is therefore locally constant there; the remaining work is continuity/patching across the excluded points.

## 5. Edge cases to exclude from the local derivative lemma

For the local lemma, exclude exactly the points where one of the coordinate formulas or one of the `thetaCandidate` branch formulas changes.

* `x=a`: the chord denominator vanishes.  This contains the vertical case `P=-Q`, where `P+Q=O`, and the tangent case `P=Q`, where the tangent formula should replace the chord formula.  For the additive proof, it is fine to remove this point locally and recover it later by continuity.
* `y=0`: this is a root/junction of the real curve.  The branch derivative `y'=f'/(2y)` is not available, and S5 assigns theta by a separate root case.
* `P=-Q`: already inside `x=a`, but worth naming because the affine output `R=(x3,y3)` is not present; the sum is `O`, where `thetaCandidate` uses its separate `O` case.
* `P=Q`: also inside `x=a` for this fixed-`Q` one-parameter chord formula.  A separate tangent analogue is possible, but for the global proof it is usually simpler to prove local constancy off this point and patch by continuity.
* `x3=e` or, more generally, `R` at a branch junction/root: the formula for `theta(R)` switches to the root value, and `sigma_hasDerivAt_of_right` requires the right-side hypothesis such as `x3>e`.
* `y3=0`: equivalent to `R` being a root once `y3^2=f(x3)` is proved.  This is the same branch-switching problem as `x3=e` in the identity-component setting.

On each connected component of the complement of these bad points, the signs of `y` and `y3` and the inequalities needed by `sigma_hasDerivAt_of_right` are stable by continuity.  That is the right setting for the derivative-zero/local-constant argument.  The continuity patch should use the already-defined values `root ↦ T` and `O ↦ 0`, not any derivative statement at the bad point itself.

## 6. Mathlib names/search terms

I would not hard-code theorem names for the affine addition formulas without inspecting the exact Mathlib version in this repo.  Likely search terms in Mathlib are:

* `WeierstrassCurve.Affine.Point`
* `WeierstrassCurve.Affine.add`
* `WeierstrassCurve.Affine.neg`
* `WeierstrassCurve.Affine.add_def`
* `WeierstrassCurve.Affine.add_eq_zero`
* `WeierstrassCurve.Affine.add_of_X_ne`
* `WeierstrassCurve.Affine.slope`
* `line`, `slope`, `chord`, `tangent`, `negOfY`

For the calculus side, the likely names/search terms are more stable:

* `HasDerivAt.sqrt` / `Real.hasDerivAt_sqrt`
* `Real.sq_sqrt`
* `Real.sqrt_pos.2`
* `Real.sqrt_ne_zero_of_pos`
* `HasDerivAt.div`
* `HasDerivAt.pow`
* `HasDerivAt.sub_const`
* `hasDerivAt_id`
* tactics: `field_simp`, `ring_nf`, `fun_prop`, `positivity`

The main recommendation is: do not initially fight Mathlib's point-addition theorem names.  Define the local real functions `chordM`, `chordX`, `chordY`, prove the algebraic identities above, and separately prove a bridge lemma saying that, away from `x=a`, the affine coordinates returned by `WeierstrassCurve.Affine.Point` addition on `shortW A B` unfold to these formulas.  Once that bridge exists, S6/S7 can use only `hasDerivAt_chordX_signed` plus the branch cases of `thetaCandidate`.
