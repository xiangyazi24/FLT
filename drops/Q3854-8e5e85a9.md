# Q3854: replacing Mordell--Weil finiteness and isolating the remaining Mazur input

You should separate the two remaining axioms sharply.

* `mordell_weil_fg` is **not irreducible** for your goal.  If it is only used to prove that the rational torsion subgroup is finite, replace it.  The most leveraged replacement is not Nagell--Lutz and not a full good-reduction injection theorem, but a refactor:

  ```text

  then torsion ⊆ ⋃ n∈S E(ℚ)[n];
  ```

## (a) Replacing `mordell_weil_fg`

### Best route if you already have bounded individual orders

If you can prove, without using torsion finiteness, that every rational torsion point has order in a finite set `S`, then torsion finiteness is immediate from your real-topology theorem.

Mathematically:

```text
E(ℚ)_tors ⊆ ⋃ n∈S E(ℚ)[n]
E(ℚ)[n] ↪ E(ℝ)[n]
|E(ℝ)[n]| ≤ 2n
⇒ E(ℚ)[n] finite
⇒ finite union finite
⇒ E(ℚ)_tors finite.
```

This is the most feasible Lean route because you already have the difficult analytic input `|E(ℝ)[n]| ≤ 2n`.  It avoids proving Mordell--Weil, avoids Nagell--Lutz, and avoids constructing reduction maps on points.

The important caveat is that the bounded-order theorem must be proved for **individual cyclic subgroups**, not using the finite abelian group structure theorem for the whole torsion subgroup.  The logical order should be:

```text
individual order restrictions
→ finite union of E[n]
→ torsion finite
→ invariant factors if needed.
```

not

```text
torsion finite
→ invariant factors
→ order restrictions.
```

If your current order-restriction proofs are phrased through invariant factors, refactor them so that the cyclic part is stated directly as:

```lean
No point of exact order n
```

or

```lean
HasRationalPointOfOrder E n → n ∈ S.
```

### Good-reduction injection route

This is the most reasonable standalone proof of torsion finiteness, but current Mathlib does not appear to have the high-level theorem you would need.

The standard proof is:

1. choose two distinct good primes `p` and `q` for an integral/minimal model of `E`;
2. define reduction maps

   ```text
   E(ℚ)_tors → E(𝔽_p),
   E(ℚ)_tors → E(𝔽_q);
   ```

3. prove prime-to-`p` torsion injects under reduction at `p`, and prime-to-`q` torsion injects under reduction at `q`;
4. conclude the product reduction map

   ```text
   E(ℚ)_tors → E(𝔽_p) × E(𝔽_q)
   ```

   is injective on torsion, because a torsion point in both kernels would have order both a power of `p` and a power of `q`, hence order `1`;
5. finite target implies finite source.

This avoids proving the full formal group has no `p`-primary torsion at a single prime; the two-prime trick only needs prime-to-`p` injectivity.

Lean cost: medium-to-large.  Mathlib has reduction of Weierstrass curves over local fields/DVRs, including integral/minimal models, `reduction`, `HasGoodReduction`, and `hasGoodReduction_iff_isElliptic_reduction`, but not a ready-made rational-point reduction map with torsion injection.  You would need to build the point-level reduction and the injectivity theorem.

### Nagell--Lutz route

Nagell--Lutz proves torsion finiteness more directly over `ℚ`:

```text
for a minimal integral equation, torsion points have integral coordinates,
and either y=0 or y² divides the discriminant.
```

Then there are finitely many possible `y`, and for each `y` finitely many `x` solving the cubic.

This is mathematically elementary compared with Mordell--Weil, but in Lean it is not obviously easier than good reduction.  You still need:

* integral/minimal Weierstrass models;
* denominator-clearing and variable-change invariance of torsion;
* local valuation arguments for torsion coordinates;
* finite divisor enumeration in `ℤ`;
* a bridge back to the rational point type used in the project.

I would not choose Nagell--Lutz unless the project already has most of this arithmetic around integral models and valuations.

### Real-topology route alone

Your theorem

```text
|E(ℝ)[n]| ≤ 2n
```

proves each individual `E(ℚ)[n]` is finite, but it does **not** prove all torsion is finite unless you already know that torsion orders are bounded or lie in a finite set.

So the real theorem is perfect for the finite-union refactor, but it is not a standalone replacement for Mordell--Weil.

### Recommended replacement hierarchy

Use the weakest statement that unblocks the proof:

1. Best no-new-axiom target, if order bounds are available:

   ```text
   bounded individual orders + finite E[n] ⇒ torsion finite.
   ```

2. Best temporary axiom:

   ```lean
   axiom rational_torsion_finite ...
   ```

3. Best standalone future proof of that axiom:

   ```text
   two-good-prime reduction injection.
   ```

4. Less attractive future proof:

   ```text
   Nagell--Lutz.
   ```

## (b) The `p=11` prime-torsion case and the minimal irreducible axiom

### Can `p=11` be proved independently?

Yes, in principle.  The classical route is:

```text
rational point of order 11 on E
⇒ noncuspidal rational point on X_1(11)
⇒ rational point on an explicit genus-one curve, isomorphic to the elliptic curve 11a3
⇒ X_1(11)(ℚ) consists only of cusps
⇒ contradiction.
```

A typical formalization route would be:

1. put `(E,P)` with `P` of order `11` into Tate normal form;
2. derive the explicit algebraic condition defining the affine model of `X_1(11)`;
3. prove a birational equivalence with the chosen elliptic curve model of `X_1(11)`;
4. prove the rational points on that elliptic curve are exactly the cusps, usually by proving rank `0` and torsion `≃ ZMod 5`, or by an explicit descent certificate;
5. map back and eliminate all noncuspidal cases.

If you already have substantial explicit descent/quartic computation infrastructure, `p=11` is a plausible contained project.  It is still not a small lemma: the hard part is not the final contradiction but the moduli/Tate-normal-form bridge and the rational-point computation on the `X_1(11)` model.

### But `p=11` is not the whole axiom

The axiom

```lean
mazur_prime_torsion_bound :
  no rational point of prime order p ≥ 11
```

also includes `p=13` and all `p ≥ 17`.

The natural split is:

```lean
axiom no_prime_order_11
    (E : WeierstrassCurve ℚ) [E.IsElliptic] :
    ¬ HasRationalPointOfOrder E 11

axiom no_prime_order_13
    (E : WeierstrassCurve ℚ) [E.IsElliptic] :
    ¬ HasRationalPointOfOrder E 13

axiom no_prime_order_ge_17
    (E : WeierstrassCurve ℚ) [E.IsElliptic] {p : ℕ}
    (hp : Nat.Prime p) (hp17 : 17 ≤ p) :
    ¬ HasRationalPointOfOrder E p
```

The first two can be attacked by explicit rational-point computations on small modular curves.  The last one is the real Mazur formal-immersion/modular-curve theorem.

### Minimal irreducible axiom for the current final theorem

For exact Mazur classification, the minimal honest axiom is still essentially the modular-curve theorem:

```lean
axiom mazur_prime_torsion_bound
    (E : WeierstrassCurve ℚ) [E.IsElliptic] {p : ℕ}
    (hp : Nat.Prime p) (hp11 : 11 ≤ p) :
    ¬ HasRationalPointOfOrder E p
```

For the weaker theorem `|E(ℚ)_tors| ≤ 16`, this is stronger than logically necessary.  A cyclic point of order `11` or `13` has cardinality `11` or `13`, so it does not itself violate the bound.  However, allowing `11` or `13` creates composite-order cases such as `22` or `26`, which do violate the cardinality bound.  Therefore the weaker theorem still needs a large-order cyclic obstruction, just not necessarily the exact statement “no prime `11` or `13`”.

A sharper cardinality-oriented axiom would be:

```lean
axiom no_rational_point_order_gt_16
    (E : WeierstrassCurve ℚ) [E.IsElliptic] {n : ℕ}
    (hn : 16 < n) :
    ¬ HasRationalPointOfOrder E n
```

plus whatever product-case exclusions are not already derivable.  This is weaker than full Mazur but still a deep cyclic-torsion theorem.  It also hides more of the arithmetic in one statement, so it is less informative than keeping `mazur_prime_torsion_bound` plus explicit composite exclusions.

If you want the cleanest long-term decomposition, use the three-piece prime split above and keep explicit composite exclusions as separate files.

## (c) Can `|E(ℚ)_tors| ≤ 16` avoid both axioms?

Not with the current mathematical ingredients.

### Avoiding `mordell_weil_fg`

Yes.  This is realistic.  Replace it by either:

* a direct `rational_torsion_finite` axiom; or
* better, a finite-union proof from bounded individual orders and your real theorem `|E(ℝ)[n]| ≤ 2n`.

This removes Mordell--Weil as an input.

### Avoiding the Mazur prime/cyclic input

No, not if the theorem is meant to be unconditional.

Any proof of

```text
|E(ℚ)_tors| ≤ 16
```

must at least exclude a rational point of prime order `p ≥ 17`, because such a point alone gives a torsion subgroup of size at least `p > 16`.

The real-topology theorem cannot exclude cyclic `p`-torsion; it only says

```text
p = |⟨P⟩| ≤ |E(ℝ)[p]| ≤ 2p,
```

which is vacuous.  The Weil pairing cannot exclude cyclic `p`-torsion either; it excludes full rational `p`-torsion.

So the best possible “avoid both” statement is:

```text
avoid Mordell--Weil, yes;
avoid a Mazur/modular-curve cyclic torsion theorem, no.
```

You can rename or weaken the Mazur input, but you cannot remove it using the current tools.

## (d) Current Mathlib surface area

I checked current Mathlib by GitHub code search and file inspection.

Mathlib has substantial Weierstrass-curve reduction infrastructure in

```lean
Mathlib.AlgebraicGeometry.EllipticCurve.Reduction
```

The file defines integral and minimal Weierstrass equations over fraction fields of DVRs, a reduction curve over the residue field, good/multiplicative/additive reduction, and proves existence of integral/minimal models and the good-reduction/elliptic-reduction equivalence.

What appears to be missing for your use is the high-level arithmetic theorem:

```text
rational torsion injects into the points of the reduction at good primes.
```

In particular, I did not find a ready point-level reduction map for `E(ℚ)` torsion with an injectivity theorem.

### Néron models

I found no usable Mathlib Néron-model API for elliptic curves.  There were no relevant code-search hits for `Neron`/`Néron` tied to `WeierstrassCurve`.

```lean
Mathlib.AlgebraicGeometry.EllipticCurve.DivisionPolynomial.Basic
```

They define the polynomial sequences `ψ`, `Ψ`, `ΨSq`, `Φ`, compute leading terms/degrees, and give a substantial algebraic foundation.
